# 🧭 COMPLIANCE MATRIX — MATRIZ DE CONTROLES TÉCNICOS & CUMPLIMIENTO

## 🎯 1. POR QUÉ (WHY / PROPÓSITO)

Documentar de forma transparente los controles técnicos de seguridad y gobernanza implementados en Baqueano, distinguiendo con honestidad profesional entre controles técnicos verificados en código y materias sujetas a revisión legal externa.

---

## ⚙️ 2. CÓMO (HOW / MATRIZ DE CONTROLES & ALCANCE)

| Dominio Normativo | Control Técnico Implementado | Estado de Verificación | Revisión Externa / Próxima Acción |
| --- | --- | :---: | --- |
| **Protección de Datos / Privacidad** | Cero PII en logs, hash de API keys, cifrado en tránsito (TLS 1.3) y reposo (AES-256) | ✅ REAL / VALIDADO | Revisión de Términos de Servicio con asesor legal nicaragüense |
| **Seguridad de Pagos (PCI-DSS)** | Alcance minimizado: Cero almacenamiento de números de tarjeta, CVV o fechas de expiración en base de datos | ✅ REAL / VALIDADO | Certificación formal con pasarela bancaria adquirente |
| **Accesibilidad Web (WCAG 2.1 AA)** | Contraste de color certificado, landmarks semánticos, navegación por teclado y etiquetas ARIA | ✅ REAL / VALIDADO | Auditoría continua con herramientas automatizadas de accesibilidad |
| **Derechos de Autor y Contenido** | Verificación de autoría de guías locales y licencias de fotografía comunitaria | ✅ REAL / VALIDADO | Firma de acuerdos de cesión de imagen con cooperativas |
| **Seguridad de APIs para Aliados** | Scopes específicos por llave, limitación de tasa (rate limiting) y revocación instantánea | ✅ REAL / VALIDADO | Formalización de convenios de interoperabilidad institucional |

## 📦 3. QUÉ (WHAT / DECLARACIÓN DE TRANSPARENCIA TÉCNICA)

- **Principio de Honestidad**: Baqueano no afirma "100% compliant" de forma contractual sin la debida validación legal y regulatoria. La plataforma implementa los controles técnicos de ingeniería de software más rigurosos para garantizar que la infraestructura esté técnicamente preparada para cualquier proceso de certificación formal.
